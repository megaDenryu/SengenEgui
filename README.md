# SengenEgui

egui の上で宣言的にUIを組む薄いラッパー。C#（Unity IMGUI）版の SengenImgui、
TypeScript（DOM）版の SengenUI と同じ精神（宣言的な構造記述・構造と装飾の分離・
利用側は素の描画APIを呼ばない）の Rust（egui）版である。

設計はC#版の「永続ノード木」の直訳ではなく、egui の即時モードに合わせてアレンジしている。
GCの無いRustでは永続木の動機（構築allocの回避）が消えるため、木は毎フレーム組み直す。
操作はクロージャでなく応答（メッセージ）として収集するため、`Rc<RefCell>` の共有参照が要らず、
描画中に状態を書き換える経路が存在しない。

## 中核の方針

1. **ノード木は1フレーム分のUI記述であり、毎フレーム組み直して捨てる。**
   ノードは状態を借りてその場の値を直接埋める。条件分岐・繰り返しも素の `if` / `map` で書ける
2. **操作は応答（利用側で定義するメッセージ型）として収集し、描画後にまとめて状態へ適用する**
3. **装飾（`スタイル`）は構造から分離し、名前付き定数として集約する**

寸法は `論理画素`（`画素(8.0)` で作る。f64 からは `論理画素::倍精度の小数から生成する`、計算用に f64 へ取り出すには `倍精度の小数にする`）、比率は `割合`（f64 からは `割合::倍精度の小数から生成する`）、向きを持つ比率の差は `割合の差`、画像に対する範囲は `割合で表した矩形`、区間の帯の上の利用する側の単位の値は `帯の値`（差は `帯の値の差`、全体の範囲は `帯の全体の範囲`）で受け取り、裸の f32 を公開APIへ出さない。

## 最小例

```rust
use sengen_egui::{子, ボタン, 文字表示, 縦積み, ノード};

#[derive(Clone)]
enum 応答 {
    加算,
}

struct 状態 {
    数: i32,
}

fn 画面(状態: &状態) -> ノード<応答> {
    縦積み(子![
        文字表示(format!("カウンタ: {}", 状態.数)),
        ボタン("+1", 応答::加算),
    ])
    .into()
}

// 毎フレーム、eguiの描画閉包の中で:
//   for 応答 in 画面(&状態).描画して集める(ui) {
//       match 応答 { 応答::加算 => 状態.数 += 1 }
//   }
```

## 見本帳

全部品を1画面に並べた見本帳を `examples/gallery` に置いている。単独クローンでは
このリポジトリのルートで次を実行する（eframe は開発用の依存としてだけ入る）。

```
cargo run --example gallery
```

GameScriptingTheory のサブモジュールとしては、そのリポジトリのルートで `cargo xtask ui-gallery` を実行する。

## リファレンス

APIの正本は rustdoc である。`cargo doc --open` で読む。公開APIには網羅して説明を付けてある。

- 糖衣ファクトリ（`ui` モジュール、`sengen_egui::` 直下に再公開）が利用側の唯一の入口。利用側は egui のAPIを直接呼ばない。口が足りないときはこのリポジトリへ足す
- 部品は「状態を借りて `ノード<M>` を返す関数」として書く
- 部品は族（同じ種類の部品のまとまり）に分かれ、`ノード` は族ごとの列挙を枝に持つ

| 族 | 部品 |
|---|---|
| 表示（応答を発しない） | 文字表示（選択できる・折り返さない・斜体/下線/取り消し線/弱い の装飾）・進捗バー・読み込み中表示・外部リンク（ブラウザで開く）・画像（最大幅・表示寸法・描く部分・表示寸法へ引き伸ばす）・一定時間で消える通知（画面の下の中央に重ねて出す。`通知の回` で新しい通知を見分ける・表示する長さ。egui の重ねる領域の仕様で、識別子ごとに最初に出した1回だけ見えない。2回目以降は出した回から見える） |
| 入力（応答を発する） | ボタン（小さい・枠なし・最小幅・有効）・チェックボックス・一行テキスト入力（伏せ字・案内文・確定時のみ発行）・複数行テキスト入力（行数・等幅）・数値入力（刻み・前置き・後置き・小数点以下の桁数）・スライダー（幅・幅いっぱい・刻み・数値を隠す・操作を終えたら発する）・ラジオボタン・選択ボタン・選択欄・色選択・リンク・押せる画像（画像の `.押されたら発する()`）・範囲枠付き画像（枠の移動と4隅での大きさの変更。新しい枠の計算は利用する側が行う。隅のつまみのため、画像の幅と高さにそれぞれ16論理画素を足した大きさを占める）・区間の帯（値の全体の範囲を1本の帯に写し、区間と位置の印を重ねて見せる。開始と終了のつまみ・区間の内側（長さを保って動かす）・位置の印の頭をドラッグし、区間の外を押すと位置の印がそこへ移る。掴んだものと値の単位の値を掴み始め・動かしている・放したで発し、丸め・最小の長さ・開始が終了を超えない規則は利用する側が持つ。幅は既定で使える幅いっぱい） |
| 容器 | 縦積み・横並び・折り返す横並び（中央寄せ・右寄せ・有効・幅・最小幅）・縦/横/両方向スクロール・仮想縦スクロール・折り畳み見出し・格子（縞模様・間隔）・ウィンドウ・パネル（上下左右・中央・装飾で地の色と余白・既定の幅と高さ・縁のドラッグで変えられる幅と高さの範囲）・タブ列・メニューバーとメニュー・モーダル・使える大きさから組む（使える幅と高さから子を組む。横並びの中では高さが行の高さしか得られないため、パネルの中か縦積みの最後に置く）・大きさを決めた領域（指定の幅と高さをちょうど占める。中央寄せ・背景色）・重ねる（識別子と下地を渡し、下地の上の9つの位置へ子を重ねる・覆って中央に置く・マウスを乗せている間だけ上に置く。重ねる子は識別子ごとに最初に出した1回だけ、大きさだけを測るため見えず押せない。2回目以降は出した回から見えて押せる） |
| 付け足し（1つの子を包む） | `.説明()`（ツールチップ）・`.右クリックメニュー()`・`.押されたら発する()`（子の範囲の全体を押せるようにする。中のボタンは優先される）（ここまで `付け足せる` トレイト）・ドラッグ元・落とし先 |
| 見えない部品 | キー操作（修飾キーの無い組は入力欄にフォーカスがある間は発しない）・落とされたファイルを受け取る（OS のファイルのパス）・描き直しを予約する（入力が無くても画面を進める間だけ置く） |
| 構造 | 余白・区切り線・無し・条件付き表示・条件で出し分ける表示 |

- 表示の出し入れは `条件付き表示` / `条件で出し分ける表示`、`if` 式の「無い側」は `無し()` を使う
- `ノード::写す` で部品ローカルの応答型を親の応答型へ埋め込める（Elm系UIの map に相当）
- `テーマ` は構造体の式で書き、書かない項目は `..テーマ::基調から作る(明暗::濃色)` で未指定にする（`スタイル` の `..スタイル::無指定` と同じ形。テーマに項目が増えても利用する側はそのままコンパイルできる）。`テーマ` で画面全体の明暗・強調色・地の色・文字色・部品の面の色・表示倍率・部品の間隔・ボタンの内余白・部品の角丸を一括適用できる。マウスを乗せた面・押した面・線・入力欄の窪んだ面などの残りの色は、指定した4つの色から混ぜて導く（導出の元が未指定の項目はeguiの既定のまま残る）。選択ボタン・選択欄の一覧・タブ列の選ばれた項目の文字は `強調色の上の文字色` で描く（未指定なら地の色と文字色のうち強調色とのコントラスト比が大きい方）。選択の縁の色は入力欄のフォーカスの枠線にも使うため変えない。文字を範囲選択できる部品（入力欄・数値入力の編集中の欄・選択できる文字表示）の範囲選択の地は、強調色を地の色の方へ寄せた色で塗る。適用しなければOSの明暗設定に追従する
- 画素から作る画像（動画のコマ等）は `差し替えられるテクスチャ` として利用側の状態に保持する。起動の部分か `App::update` で egui の本体を渡して `登録して作る` で作り、中身が変わったときだけ描画の外で `差し替える`（`画素の並び` は赤・緑・青・不透明度の各1バイトの列を借りるが、登録と差し替えのたびに、egui が所有した画像を要求するため1コマ分の領域を確保して写す）。部品へは `画像(&テクスチャ)`・`範囲枠付き画像(&テクスチャ, …)` の形で渡す。テクスチャを借りられない場所（`使える大きさから組む` の閉包）へは `テクスチャ.参照を複製する()` で得た `登録したテクスチャの参照` を所有させて持ち込み、同じ2つの部品へ渡す
- 日本語フォントは、起動の部分で `日本語フォントの候補::標準で入っている候補().最初に読めたものを設定する(eguiの本体)` を1回呼んで足す（Windows の游ゴシック・メイリオ等、Linux の Noto Sans CJK、macOS のヒラギノ角ゴシックを順に試す）。読めない・先頭のバイトがフォントの形式でないファイルは飛ばし、どれも使えなければ置き場所ごとの理由を持つ失敗を返す。起動を止めるかどうかは利用する側が決める。足したフォントの字形は egui の既定のフォント（英字）と縦の位置がずれるため、標準の候補は測った縦の補正（`字形の縦の補正`。字の大きさに対する比で、正は下）を持つ（游ゴシック 0.26・メイリオ 0.04・MS ゴシック 0。Linux と macOS は未測定で 0）。自分で選んだフォントの補正量は `日本語フォントの候補::補正付きの一覧から作る` と `フォントの置き場所と補正::生成する` で指定する。自分のフォントの補正量は、このリポジトリのルートで `SENGEN_EGUI_FONT_TO_MEASURE=<フォントの置き場所> cargo test --test font_correction_search -- --ignored --nocapture` を実行すると、標準の候補と同じ測り方で探して表示する
- 色・キー・修飾キーは egui の `Color32`・`Key`・`Modifiers` を `色`・`キー`・`修飾キー` の名前で再公開している。利用する側は egui を名指さずに色の定数とキーの組を書ける
- 画像を URI から出すには、利用側が起動時に画像の読み込み器（egui_extras 等）を導入する。読み込み器なしで出せるのは登録済みのテクスチャだけである

## 利用形態

他のリポジトリで使うときの導入・画面の書き方・足りない口の足し方は [docs/他のリポジトリで使う.md](docs/他のリポジトリで使う.md) が1通りに定める。要点は次の3つである。

- 利用する側は Cargo の git 依存を `rev` で固定して取り込み、SengenEgui を書き足すPCでだけ、親ディレクトリの `.cargo/config.toml` の `[patch]` で手元の複製へ差し替える
- 利用する側の eframe（または egui）は、本リポジトリの egui と同じマイナー版に揃える
- 口が足りないときは、利用する側で素の egui を呼んで回避せず、本リポジトリへ口を足してから利用する側の `rev` を上げる

単独クローンでも `cargo test` が通る自己完結の定義を保つ。GameScriptingTheory は導入の経緯から Git サブモジュールとして埋めており、上の文書の手順の対象外である。

利用例: [GameScriptingTheory](https://github.com/megaDenryu/GameScriptingTheory) の `crates/devtool`（開発ツールGUI）。
