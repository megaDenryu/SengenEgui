# SengenEgui

egui の上で宣言的にUIを組む薄いラッパー。C#（Unity IMGUI）版の SengenImgui、
TypeScript（DOM）版の SengenUI と同じ精神（宣言的な構造記述・構造と装飾の分離・
利用側は素の描画APIを呼ばない）の Rust（egui）版である。

設計はC#版の「永続ノード木」の直訳ではなく、egui の即時モードに合わせてアレンジしている。
GCの無いRustでは永続木の動機（構築allocの回避）が消えるため、木は毎フレーム組み直す。
操作はクロージャでなく応答（メッセージ）として収集するため、`Rc<RefCell>` の共有参照が要らず、
描画中に状態を書き換える経路が存在しない。

## 中核の方針

1. **ノード木は1フレーム分のUI記述であり、毎フレーム組み直して捨てる。**
   ノードは状態を借りてその場の値を直接埋める。条件分岐・繰り返しも素の `if` / `map` で書ける
2. **操作は応答（利用側で定義するメッセージ型）として収集し、描画後にまとめて状態へ適用する**
3. **装飾（`スタイル`）は構造から分離し、名前付き定数として集約する**

寸法は `論理画素`（`画素(8.0)` で作る）、比率は `割合`、向きを持つ比率の差は `割合の差`、画像に対する範囲は `割合で表した矩形` で受け取り、裸の f32 を公開APIへ出さない。

## 最小例

```rust
use sengen_egui::{子, ボタン, 文字表示, 縦積み, ノード};

#[derive(Clone)]
enum 応答 {
    加算,
}

struct 状態 {
    数: i32,
}

fn 画面(状態: &状態) -> ノード<応答> {
    縦積み(子![
        文字表示(format!("カウンタ: {}", 状態.数)),
        ボタン("+1", 応答::加算),
    ])
    .into()
}

// 毎フレーム、eguiの描画閉包の中で:
//   for 応答 in 画面(&状態).描画して集める(ui) {
//       match 応答 { 応答::加算 => 状態.数 += 1 }
//   }
```

## 見本帳

全部品を1画面に並べた見本帳を `examples/gallery` に置いている。単独クローンでは
このリポジトリのルートで次を実行する（eframe は開発用の依存としてだけ入る）。

```
cargo run --example gallery
```

GameScriptingTheory のサブモジュールとしては、そのリポジトリのルートで `cargo xtask ui-gallery` を実行する。

## リファレンス

APIの正本は rustdoc である。`cargo doc --open` で読む。公開APIには網羅して説明を付けてある。

- 糖衣ファクトリ（`ui` モジュール、`sengen_egui::` 直下に再公開）が利用側の唯一の入口。利用側は egui のAPIを直接呼ばない。口が足りないときはこのリポジトリへ足す
- 部品は「状態を借りて `ノード<M>` を返す関数」として書く
- 部品は族（同じ種類の部品のまとまり）に分かれ、`ノード` は族ごとの列挙を枝に持つ

| 族 | 部品 |
|---|---|
| 表示（応答を発しない） | 文字表示（選択できる・折り返さない・斜体/下線/取り消し線/弱い の装飾）・進捗バー・読み込み中表示・外部リンク（ブラウザで開く）・画像（最大幅・表示寸法・描く部分・表示寸法へ引き伸ばす） |
| 入力（応答を発する） | ボタン（小さい・枠なし・最小幅・有効）・チェックボックス・一行テキスト入力（伏せ字・案内文・確定時のみ発行）・複数行テキスト入力（行数・等幅）・数値入力・スライダー・ラジオボタン・選択ボタン・選択欄・色選択・リンク・押せる画像（画像の `.押されたら発する()`）・範囲枠付き画像（枠の移動と4隅での大きさの変更。新しい枠の計算は利用する側が行う。隅のつまみのため、画像の幅と高さにそれぞれ16論理画素を足した大きさを占める） |
| 容器 | 縦積み・横並び・折り返す横並び（中央寄せ・右寄せ・有効・幅・最小幅）・縦/横/両方向スクロール・仮想縦スクロール・折り畳み見出し・格子（縞模様・間隔）・ウィンドウ・パネル（上下左右・中央）・タブ列・メニューバーとメニュー・モーダル |
| 付け足し（1つの子を包む） | `.説明()`（ツールチップ）・`.右クリックメニュー()`（`付け足せる` トレイト）・ドラッグ元・落とし先 |
| 見えない部品 | キー操作 |
| 構造 | 余白・区切り線・無し・条件付き表示・条件で出し分ける表示 |

- 表示の出し入れは `条件付き表示` / `条件で出し分ける表示`、`if` 式の「無い側」は `無し()` を使う
- `ノード::写す` で部品ローカルの応答型を親の応答型へ埋め込める（Elm系UIの map に相当）
- `テーマ` で画面全体の明暗・強調色・地の色・文字色・部品の面の色・表示倍率・部品の間隔・ボタンの内余白・部品の角丸を一括適用できる。マウスを乗せた面・押した面・線・入力欄の窪んだ面などの残りの色は、指定した4つの色から混ぜて導く（導出の元が未指定の項目はeguiの既定のまま残る）。適用しなければOSの明暗設定に追従する
- 画像を URI から出すには、利用側が起動時に画像の読み込み器（egui_extras 等）を導入する。読み込み器なしで出せるのは登録済みのテクスチャだけである

## 利用形態

他のリポジトリで使うときの導入・画面の書き方・足りない口の足し方は [docs/他のリポジトリで使う.md](docs/他のリポジトリで使う.md) が1通りに定める。要点は次の3つである。

- 利用する側は Cargo の git 依存を `rev` で固定して取り込み、SengenEgui を書き足すPCでだけ、親ディレクトリの `.cargo/config.toml` の `[patch]` で手元の複製へ差し替える
- 利用する側の eframe（または egui）は、本リポジトリの egui と同じマイナー版に揃える
- 口が足りないときは、利用する側で素の egui を呼んで回避せず、本リポジトリへ口を足してから利用する側の `rev` を上げる

単独クローンでも `cargo test` が通る自己完結の定義を保つ。GameScriptingTheory は導入の経緯から Git サブモジュールとして埋めており、上の文書の手順の対象外である。

利用例: [GameScriptingTheory](https://github.com/megaDenryu/GameScriptingTheory) の `crates/devtool`（開発ツールGUI）。
