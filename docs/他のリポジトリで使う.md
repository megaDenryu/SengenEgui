# 他のリポジトリで SengenEgui を使う

## この文書の読み手と目的

この文書の主な読み手は、別のリポジトリで「SengenEgui を使って画面を作って」と頼まれた AI エージェントである。次の読み手は、その作業を検収するオーナーである。

この文書は、導入の方法・画面の書き方・足りない機能の足し方を1通りに決める。頼まれるたびに AI が方法を選び直すと、リポジトリごとに依存の書き方や初期化が食い違い、SengenEgui の更新を取り込めなくなるためである。この文書に書いた手順と違う方法を選ぶときは、作業を始める前にオーナーの承認を得る。

## 用語

- **利用する側**とは、SengenEgui に依存して画面を作るリポジトリのことである。
- **口**とは、SengenEgui が利用する側へ公開している関数・メソッド・設定項目のことである（例: `ボタン`、`テーマ` の `文字色`）。
- **口が足りない**とは、利用する側でやりたい表示や操作があるのに、SengenEgui にそのための口がまだ無い状態のことである。
- **手元の複製**とは、SengenEgui を書き足すPCで、利用する側のリポジトリと同じ親ディレクトリに置いた SengenEgui のクローンのことである（例: `C:\devs\SengenEgui`）。
- **`ノード`** とは、1フレーム分の画面の構造を表す SengenEgui の値のことである。画面の部品（ボタン・文字表示・縦積み等）はどれも `ノード` に変換できる。
- **応答**とは、利用する側が定義する列挙型の値であり、ボタンを押す等の操作が発する要求のことである。`ノード<応答>` の型引数がこの型を指す。
- **`描画して集める`** とは、`ノード` を egui の上に描き、描いている間に操作が発した応答をまとめて返す、`ノード` のメソッドのことである。
- **`テーマ`** とは、画面全体の明暗・色・間隔を一括で決める SengenEgui の値のことである。その項目の **`基調`** は、画面の明暗（濃色か淡色か）を決める。
- **`スタイル`** とは、1つの部品に付ける装飾（文字の大きさ・色・背景・余白等）を表す SengenEgui の値のことである。
- **中核の方針**とは、SengenEgui の README の「中核の方針」の節にある次の3つの決まりのことである。(1) 画面の構造は毎フレーム組み直して捨てる。(2) 操作は応答として集め、描画の後でまとめて状態へ適用する。(3) 装飾はスタイルの名前付き定数として構造から分けて集める。

## 導入の方法

利用する側は、SengenEgui を Cargo の git 依存として、コミットを `rev` で固定して取り込む。SengenEgui を書き足すPCでだけ、Cargo の `[patch]` で git 依存を手元の複製へ差し替える。

この方法を選ぶ理由は、利用する側で画面を作る途中に口が足りなくなることが多いからである。利用する側のPCで差し替えておけば、SengenEgui を直した結果がそのまま利用する側のビルドに反映され、直す場所は SengenEgui の1つだけで済む。差し替えていない他のPCや他の人の環境は、`rev` で固定した版のまま動く。

Git サブモジュールとして埋め込む方法は新しいリポジトリでは使わない。サブモジュールは、サブモジュールの中でのコミットと親の参照先の更新という2段の手順を毎回要求し、`--recursive` を付け忘れたクローンでは中身が空になるためである。GameScriptingTheory は導入の経緯からサブモジュールで使っており、この文書の手順の対象外である。

crates.io へは公開していない。

## 手順1: 依存を書く

1. SengenEgui の最新のコミットを調べる。実行場所はどこでもよい。

   ```
   git ls-remote https://github.com/megaDenryu/SengenEgui refs/heads/main
   ```

2. 利用する側のパッケージの `Cargo.toml` に依存を書く。`rev` には手順1で得たコミットの値を書く。`rev` を書かずにブランチを追う形にしない。`cargo update` を実行しただけで、SengenEgui の版が知らないうちに変わるためである。

   ```toml
   [dependencies]
   sengen_egui = { git = "https://github.com/megaDenryu/SengenEgui", rev = "<コミットの値>" }
   eframe = "0.32"
   ```

3. 利用する側の eframe（または egui）のマイナー版を、SengenEgui の `Cargo.toml` にある egui の版（2026-09-26 時点で `0.32`）と揃える。版がずれると egui が2つ入り、SengenEgui の型と利用する側の型が合わなくなってビルドが落ちる。揃ったかどうかは、利用する側のリポジトリのルートで次を実行して確かめる。egui が1つの版だけ表示されれば揃っている。

   ```
   cargo tree -i egui
   ```

## 手順2: 起動の部分を書く

利用する側は、起動の部分（窓の作成と、テーマの適用・フォントの設定・テクスチャの登録へ egui の本体を渡すこと）だけで素の eframe と egui を使う。画面の中身は SengenEgui の口だけで組む。見本は SengenEgui の `examples/gallery/main.rs` にあり、次の形を写す。

- 窓を作る処理（eframe の作成の閉包）の中で `テーマ::適用する` を1回呼ぶ。`テーマ::適用する` は egui の明暗の選択を `基調` に固定するため、OS の明暗設定が淡色でも濃色でも、指定した配色で表示される。
- 日本語フォントは、同じ作成の閉包の中で `日本語フォントの候補::標準で入っている候補().最初に読めたものを設定する(&作成文脈.egui_ctx)` を1回呼んで足す。egui の既定のフォントは日本語の字形を持たないためである。どのフォントも読めなければ失敗が返るため、利用する側はその失敗を表示して起動を続ける。
- eframe の `App::update` の中で、状態を借りて `ノード` を組み、`描画して集める` で描画し、返ってきた応答を描画の後でまとめて状態へ適用する。描画の途中で状態を書き換えない。
- 画素から作る画像（動画のコマ等）は、`差し替えられるテクスチャ::登録して作る` に egui の本体（作成の閉包の `egui_ctx`、または `App::update` が受け取るもの）を渡して作り、状態に保持する。中身が変わったときだけ、描画の外（`描画して集める` の前か、応答を適用する段）で `差し替える` を呼ぶ。画面の関数には `画像(&テクスチャ)` の形で渡すだけであり、egui の本体を渡さない。`使える大きさから組む` の閉包のように所有した値だけを持ち込める場所では、`テクスチャ.参照を複製する()` で得た `登録したテクスチャの参照` を閉包へ所有させる。見本は `examples/gallery/sample_player.rs` にある。

## 手順3: 画面を書く

- 画面は、状態を借りて `ノード<応答>` を返す関数として書く。部品は `sengen_egui::` の直下に再公開された関数（`縦積み`・`ボタン`・`文字表示` 等）だけで組む。
- 色の定数は `色`（egui の `Color32` の再公開）で書き、キーの組は `キー` と `修飾キー` で書く。画面のコードで `egui::` を名指さない。
- 装飾は `スタイル` の名前付き定数として1つのファイル（例: `styles.rs`）に集め、部品からは `.装飾(定数名)` で参照する。
- 使える部品の一覧は SengenEgui の README の部品の表にある。実際の見た目と操作は見本帳で確かめる。見本帳は、手元の複製のルートで次を実行すると起動する。

  ```
  cargo run --example gallery
  ```

- API の正本は rustdoc である。手元の複製のルートで `cargo doc --open` を実行すると読める。

## 口が足りないとき

口が足りないかどうかは、「利用する側の画面のコードが素の egui を呼ばないと実現できないか」で判定する。利用する側の画面のコードが素の egui を呼ばないと実現できないなら、口が足りない。

口が足りないときは、利用する側で素の egui を呼んで回避してはならない。回避した箇所は中核の方針（用語の節で定めた3つの決まり）の外に出るため、テーマや応答の収集が効かなくなり、同じ回避がリポジトリごとに別の形で増える。次の手順で SengenEgui へ口を足す。

1. 手元の複製が無ければ作る。実行場所は、利用する側のリポジトリの親ディレクトリ（例: `C:\devs`）である。

   ```
   git clone https://github.com/megaDenryu/SengenEgui
   ```

2. 差し替えの設定を書く。置き場所は、利用する側のリポジトリの親ディレクトリの `.cargo/config.toml`（例: `C:\devs\.cargo\config.toml`）である。Cargo は作業ディレクトリから上の階層へ向かって `.cargo/config.toml` を探して合わせて読むため、この場所に書くと、どのリポジトリにもコミットされず、その親ディレクトリの下のすべてのリポジトリで差し替えが効く。利用する側のリポジトリの中の `.cargo/config.toml` には書かない。その中の設定はコミットされて、手元の複製を持たない環境のビルドを壊すためである。`path` は、`.cargo` ディレクトリを置いたディレクトリからの相対で書く。

   ```toml
   [patch."https://github.com/megaDenryu/SengenEgui"]
   sengen_egui = { path = "SengenEgui" }
   ```

   差し替えが効いているかは、利用する側のリポジトリのルートで `cargo tree -i sengen_egui` を実行して確かめる。手元の複製のパスが表示されれば効いている。手元の複製を消したPCでは、この設定も消す。`path` の先が無いと、Cargo はビルドを始められない。

3. 手元の複製で口を足す。足し方は SengenEgui の README と `src/lib.rs` の方針に従う。部品は族（表示・入力・容器・付け足し・見えない部品）のどれかに入れ、公開する口には説明を書き（`#![warn(missing_docs)]` が有効である）、テストを `tests/` に足し、見本帳に載せる。

4. 手元の複製のルートで検証してから、SengenEgui のリポジトリでコミットして push する。

   ```
   cargo fmt --check
   cargo clippy --all-targets -- -D warnings
   cargo test
   ```

5. 利用する側の `Cargo.toml` の `rev` を、4で push したコミットへ上げてコミットする。手順4より先に行わない。push していないコミットを `rev` に書くと、他の環境では取得できずビルドが落ちるためである。

手順5を忘れると、差し替えているPCでは新しい口が使えるのに、他の環境では古い版のままビルドが落ちる。口を足した作業は、手順5のコミットまでを1組として終える。

## egui の版を上げるとき

SengenEgui の egui を先に上げ、SengenEgui でコミットして push する。そのあと、利用する側で eframe の版と `rev` を同じコミットの中で上げる。どちらか片方だけ上げると、手順1の3で書いたとおり型が合わずにビルドが落ちる。

## やってはいけないこと

- 利用する側の画面のコードで素の egui を呼ぶ（起動の部分を除く）。
- SengenEgui のソースを利用する側のリポジトリへ写して置く。
- `rev` を書かずにブランチを追う形で依存を書く。
- 差し替えの設定を、利用する側のリポジトリの中の `.cargo/config.toml` に書いてコミットする。
- 新しいリポジトリで SengenEgui を Git サブモジュールとして埋め込む（オーナーの承認がある場合を除く）。
